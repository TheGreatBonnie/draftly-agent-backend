# Diagram Rules

Rules for generating and editing diagrams in documentation.

## Style

- Use Mermaid for architecture and flow diagrams.
- Keep diagrams small and focused: one idea per diagram.
- Use consistent shapes: round nodes for steps, diamonds for decisions.

## Labels

- Label every edge with a verb phrase describing the transition.
- Use sentence case in node labels; no trailing periods.

## Placement

- Place a diagram directly after the paragraph that introduces it.
- Always provide a text summary alongside the diagram for accessibility.

## Accuracy

- Diagrams must match the surrounding prose and the real system.
- Never invent components that do not exist.
- When in doubt, omit the diagram rather than approximate.
