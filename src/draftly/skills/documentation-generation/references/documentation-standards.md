# Documentation Standards

Defines the structural and quality requirements for all documentation pages generated by Draftly.

## Page Structure

Every documentation page must include:

| Element | Required | Description |
|---------|----------|-------------|
| Frontmatter | Yes | `title`, `description`, `tags` (array) |
| H1 Title | Yes | Matches frontmatter `title` |
| Overview | Yes | One paragraph answering "what and why" |
| Prerequisites | Conditional | Required for tutorials and how-to guides |
| Body Sections | Yes | Descriptive H2 headings, parallel structure |
| Related Links | Yes | Cross-references to related pages |

## Frontmatter Schema

```yaml
title: "Page Title"
description: "One-sentence summary for search and link previews"
tags: ["category", "feature", "audience"]
```

## Naming Conventions

- Files: `kebab-case.md` (e.g., `getting-started.md`)
- Headings: Sentence case (e.g., "Configure authentication")
- Code identifiers: `backticks` (file paths, commands, parameters)
- Placeholders: `<angle-brackets>` (e.g., `<api-key>`)

## Quality Gates

Before delivery, every page must pass:

1. **Frontmatter validation** — all required fields present, valid YAML
2. **Link validation** — no broken relative links, anchors resolve
3. **Structure check** — headings form logical outline (H1 → H2 → H3)
4. **Code examples** — fenced blocks have language tags, render correctly
5. **Evidence traceability** — claims reference source (PR, issue, code path)

## File Organization

```
docs/
  ├── getting-started/
  │   ├── quickstart.md
  │   └── installation.md
  ├── guides/
  │   ├── how-to-*.md
  │   └── tutorials/
  ├── concepts/
  │   └── *.md
  └── reference/
      ├── api/
      └── cli/
```

Group by user intent, not internal architecture. Prefer flat structure over deep nesting.
