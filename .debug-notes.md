# Worker failure root-cause notes (run 2a3b02a0, PR #45)

## Bug 1 — deterministic crash (BLOCKING)
- `documentation_page_states.status` is `NOT NULL` with **no default** (migration 060).
- `PageWorkflowRepository.create_pages` (repository.py:115-127) INSERTs only
  `run_id, org_id, page_id, path, action` → every seeded page row gets `status = NULL`.
- Postgres raises `NotNullViolationError` → `_seed()` → `page_workflow_failed` →
  whole `github_pr.enqueue` task fails. This is an app bug, not a PR-content issue.
- Fix: INSERT `status = 'pending'` + new migration 061 setting `DEFAULT 'pending'`.

## Bug 2 — impact agent search failures → single fabricated doc
- The `impact` agent issued 4 search calls (2× keyword_search, 2× semantic_search).
  All failed argument binding ("expects a string but gave list" — the model emitted
  a JSON array for `query`/`namespace`, which the `str` signature rejects).
- After 4 failures the model gave up, never enumerated the repo docs tree
  (`github_get_tree`/`github_read_file` WERE available), and fabricated a plan for
  `docs/oauth.md` — a legacy filename that does not exist in the repo.
- Fix (two layers):
  1. Tool layer: coerce list/None string-args to a joined string (defense-in-depth,
     keeps the docs-namespace RAG delegation working).
  2. Guidance layer: exact scalar call format + repo-tree fallback in IMPACT_PROMPT,
     github-pr-analysis SKILL.md, and documentation-impact.md, plus the rule that
     `affected_documents` must be real paths observed in the repo.
